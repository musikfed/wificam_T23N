# PegineLab WIFICAM T23N: режим «ИИ / Голос» с внешней программой

## Что делает галочка

В новой Web UI на главной странице есть карточка **LLM / GPT напарник** и вкладка **ИИ / Голос**. По умолчанию режим выключен. Переключатель устанавливает или удаляет разрешение `/opt/wificam/services/llm_companion.enabled` через защищённый CGI. После перезагрузки выбор сохраняется на SD. **На самой камере GPT, распознавание или синтез речи не запускаются**; выключенная опция не создаёт новых демонов и не открывает порт.

Галочка пока означает **разрешить внешнему мосту работать**, а не уже работающий голосовой разговор. В статусе «Внешний мост» выводится только недавний heartbeat; отсутствие подтверждённого звукового канала явно обозначено. Никакая видеозапись или аудиопередача не запускается от одного переключения.

## Что требует внешняя программа

```text
Galayou G2 (T23N: SC2336 + ATBM6012BX)
  ├─ RTSP / HTTP JPEG video ---> Host PC / Huananzhi (optional image context)
  ├─ Raptor RAD microphone ---> Host STT ---> Local LLM or GPT
  └─ Camera speaker <--- Host TTS and hardware-compatible talkback bridge
```

Реально присутствующий в профиле Raptor RAD подтверждает *задуманную* поддержку аудиозахвата, но микрофонный аудиотрек, вывод речи на динамик и формат talkback **ещё нужно проверить на физической камере**. В `wificam-camera-ctl` пока **нет** команды воспроизведения аудио. Не обещать беседу через встроенный динамик до аппаратного теста.

Стандартный **RTSP по Wi-Fi** не зависит от WebRTC, RTMP, SRT, WebTorrent или USB webcam. Но WebRTC **действительно является сетевым протоколом для видео и двустороннего звука**, полезным для низкой задержки/браузера. Поэтому он не вырезан из проекта навсегда: `WIFICAM_WEBRTC=1` при *новой сборке* включает поддержку WebRTC/TLS в Raptor. По умолчанию `WIFICAM_WEBRTC=0`, чтобы беречь ресурсы. Это **параметр сборки**, а не состояние галочки на уже запущенной камере. WebTorrent/RTMP/SRT/USB-webcam остаются выключенными в минимальном профиле.

## Протокол интеграции с внешним мостом

Порт 8090 — существующая Web UI PegineLab, защищённая Basic Auth + CSRF. Сначала обязательно исправить реальное выполнение CGI, иначе S90 безопасно **не запускает порт 8090**.

- `GET /cgi-bin/api?op=assistant_status` — JSON: `{"ok":true,"enabled":false,"connected":false,"state":"disabled","backend":"external"}`. Требуется Basic Auth. Секреты и пароли в ответе отсутствуют.
- `POST /cgi-bin/api?op=assistant_toggle` — поля `enabled=1|0&csrf=...`. Только авторизованная Web UI, с CSRF. Действие сохраняет маркер и при выключении сбрасывает сигнал внешнего моста.
- `POST /cgi-bin/api?op=assistant_heartbeat` — поле `csrf=...`; требуется Basic Auth и включённый режим. Обновляет временную метку только в `/var/run`. Статус `bridge_online` действует 90 секунд после последнего сигнала. Heartbeat **не подтверждает**, что звук или LLM отвечают.

Внешняя программа должна запрашивать статус, работать **только когда enabled=true**, отправлять heartbeat при фактической работе, прекращать захват/отправку медиа сразу после выключения режима и очищать временные ресурсы при остановке. Это протокол интерфейса; реальный STT/LLM/TTS медиамост — отдельный компонент, который ещё не установлен и не внедрён в прошивку.

### Безопасность

Никаких API-ключей GPT, аудиофайлов и облачных токенов в Git, CGI, HTML или SD rootfs. Хранить ключи только в настройках внешнего сервера. Доступ разрешать только в доверенной LAN или VPN (обычный HTTP Basic Auth на :8090 не шифрует пароль и не подходит для выхода в интернет). Не открывать :8090 наружу. Безопасный запуск возможен только после CGI hardware PASS.

Видео/RTSP/PTZ и SSH должны работать независимо от LLM-переключателя. Голосовой режим по умолчанию выключен; сценарий и согласие пользователя должны предшествовать передаче записей третьим сторонам.

## Где что находится

- `web/index.html`, `web/app.js`, `web/styles.css` — интерфейс переключателя и индикация.
- `web/cgi-bin/api` — серверный переключатель и heartbeat.
- `tests/test_assistant_cgi.py` — проверки состояния, авторизации, CSRF и протухания heartbeat в GitHub CI.
- `scripts/build_thingino_wificam_image.sh` — `WIFICAM_WEBRTC` для будущей voice-ready сборки.

Этот документ не объявляет голосового напарника аппаратно проверенным. Сначала требуется запуск `:8090` с работающим CGI, затем независимая проверка аудио входа/выхода.

## Обязательное аппаратное аудио (обновлено)

Собираемый профиль T23N теперь **обязательно** содержит Raptor RAD, RAC, `/usr/sbin/microphone`, `/usr/sbin/speaker` и `/usr/sbin/play`; наличие каждого из файлов проверяется и в результирующей ext4 SD-корневой системе. Если хоть один инструмент отсутствует, сборка аварийно завершается, а не выдаётся как пригодная для разговора. Штатный Thingino `play -s -r 16000 -` передаёт PCM в `rac play`; Hombo3 имеет `backend/app/camera_speaker.py`, который отправляет это PCM через SSH.

**Но:** проверка файлов не доказывает, что на физической камере выведен звук из динамика, доступна RTSP аудиодорожка, включён аудиовыход `ao_enabled` или корректно подключён усилитель. До подтверждения обеих физических сторон разговор помечается как неподтверждённый. Голосовой код Hombo3 до интеграции не читает флаг `assistant_status` камеры: оба согласия/настройки нужно согласовать отдельно.
