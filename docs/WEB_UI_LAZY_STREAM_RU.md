# PegineLab WIFICAM T23N — ленивый Web UI без помех Hombo3

**Статус:** исправлено в исходниках `main`. Старая карта с
`0.1_test` **не содержит** этих правок; новое поведение появится
только после сборки нового SD-образа и аппаратной проверки.

## Цель

- **Hombo3 на Windows 11 Acer** постоянно использует RTSP/FFmpeg CameraHub
  для компьютерного зрения, при необходимости микрофон RTSP.
- **Web UI T23N :8090** нужен для диагностики, Wi-Fi, настроек и PTZ;
  он не должен запускать *второй* видеопоток без явного запроса.
- Вебморда и Hombo3 могут работать **одновременно**.
- Закрытие вебморды, уход с вкладки «Видео», сворачивание/скрытие
  окна или переход назад должны **закрывать только вебподписку**,
  оставляя Raptor/RTSP/Hombo3 работать.
- Не удалять и не сбрасывать `drop_caches` ядра Linux. Это общий
  файловый кеш, а не отдельный кеш просмотрщика; его очистка может
  ухудшить время реакции.

## Реализация

```text
T23N ISP / RVD (общий источник)
     ├── RSD → RTSP ch0/ch1 → Acer Windows Hombo3 CameraHub
     │                            └── YOLO / VectorProbe / LLM
     └── RHD → JPEG/MJPEG (по требованию)
                   └── BusyBox CGI /cgi-bin/live.mjpg
                            └── :8090 Web UI, только после ▶ Смотреть
```

При открытии интерфейса грузятся только HTML/CSS/JS и один небольшой
JSON-запрос статуса. Никаких тегов `img src` для видео при первом
открытии; сканирование дополнительных сервисов — только на вкладке
«Сеть». Опрос состояния — раз в 60 секунд, только на страницах
системы/сети/статуса при видимом окне.

При переходе в «Видео» сразу доступны кнопки PTZ и реверса, но
**видео выключено до нажатия ▶ «Смотреть видео»**.

`live.mjpg` использует один непрерывный клиент `curl` к
локальному Raptor RHD вместо запуска отдельного
`raptorctl rvd save jpeg` на каждом кадре. Серверный скрипт
`exec curl` не создаёт бесконечный цикл со своими фоновыми
процессами. При отключении HTTP-клиента выход curl ожидается
по закрытому сокету/каналу вывода. Это нужно подтвердить
на конкретном BusyBox httpd и Raptor.

Если MJPEG недоступен, идёт **один JPEG каждые ~2 секунды**,
новый снимок запрашивается только после успешной загрузки
предыдущего, без очереди параллельных запросов.

При выходе с видео `stopPreview()` удаляет `img.src`, выключает
обработчики, очищает таймер и прерывает HTTP MJPEG.
При `visibilitychange(hidden)` и `pagehide` происходит то же.
При возврате пользователь нажимает «Смотреть» **вручную**:
фоновой автоподписки нет. Кнопки `camera_start`/`camera_stop`
удалены с панели, чтобы не прервать Hombo3.

В Windows интерфейсе Hombo3 скрытие вкладки
закрывает **только браузерный WebSocket и MJPEG fallback**,
освобождает Blob URL и изображение; backend CameraHub и его
RTSP reader на Acer продолжают работать для распознавания.

## Что реально освобождается

- Подписка конкретного браузера на MJPEG, CGI-процесс/curl
  после корректного обнаружения отключения клиента;
- таймер опроса JPEG и его HTTP-запросы;
- DOM-изображение и Blob URL браузера, если они есть;
- вторичный сетевой видеотрафик Web UI.

**Не останавливаются:** `rvd`, `rsd`, `rad`, `rhd`, `motors-daemon`,
SSH/Dropbear, Wi-Fi, ядро/ISP, RTSP-сессия Hombo3. Кеш/пулы
видеокодировщика могут остаться в памяти Raptor для основного потока —
это нормально; принудительно освобождать их, нарушая Hombo3, нельзя.

## Аппаратные тесты после новой сборки SD

На Acer под WSL:

```sh
cd ~/myipcam/wificam_T23N
git switch main
git pull --ff-only origin main
# Пока SD не пересобран, новый UI на камере не появится.
# Файлы на GitHub сами по себе НЕ обновляют образ.
```

На самой T23N по SSH (безопасно, только чтение):

```sh
pidof rvd rsd rhd rad motors-daemon
ps w | grep -E '[c]url.*mjpeg|[h]ttpd|[r]vd|[r]sd|[r]hd'
cat /proc/loadavg
free
netstat -tn 2>/dev/null | grep -E ':554|:8090'
```

Ручной сценарий:
1. Hombo3 Windows показывает видео по RTSP. Открыть `:8090/`:
   не должно быть лишнего потока `/live.mjpg`, FPS Hombo3 не падает.
2. Открыть вкладку «Видео» без нажатия «Смотреть»: второго MJPEG
   клиента **нет**; команды PTZ доступны отдельно.
3. Нажать «Смотреть»: MJPEG появляется, Hombo3 продолжает получать RTSP.
4. Нажать «Отключить видео», перейти на другую вкладку, свернуть браузер,
   закрыть страницу: веб-соединение пропадает, `curl /mjpeg` освобождается.
5. После возвращения видео **не запускается самостоятельно**.
6. Повторить с выключенным `rhd` только если уже остановлен:
   UI должен перейти на редкие JPEG, но **не выключать Raptor для теста**.
7. Сравнить загрузку CPU, RSS, сетевой трафик и задержку PTZ в
   режимах Hombo-only / Hombo+Web / Hombo-after-close. Не путать
   память ядра в cache с утечкой.
8. Подтвердить SSH после reboot, API JSON, работу микрофона и RTSP.

## CI

`node scripts/test_web_lazy_preview.js` запускает настоящий `web/app.js`
с макетом DOM: проверяет отсутствие кадров при старте, явную подписку,
отключение при переключении вкладок, паузу в фоне, прекращение
снимков, удаление опасных кнопок `camera_stop`.
GitHub Actions не заменяет тест на физической T23N.
